# Acceptance Criteria: prop-overview-range-panel

## User-Visible Criteria

- A1：modern显示已批准三分区、主净收益/ROI、真实累计走势、同刻度收支与当前账号分布；没有本月重复指标、已回本标签或集中说明菜单。验证：隔离浏览器、截图审阅。
- A2：快捷范围和自定义起止日期应用后，本面板财务值及走势图同步；取消草稿保持原值。下方月度/漏斗和账号当前阶段不被误改。验证：纯函数与浏览器交互。
- A3：六个字段的说明只解释本字段，hover/focus/tap可读，Escape/移出或外部点击能关闭；手机44px目标，提示不被卡片裁切。验证：浏览器与DOM断言。
- A4：经典布局原五指标输出不变；现代明暗、7配色、自定义盈亏色、中英、375/390/1280/1600px不出现金额裁切或页面横向溢出。验证：HTML基线及离线视觉检查。

## System Criteria

- A5：范围/说明/重绘操作无新增远端请求或业务写入；新浮层和范围在身份/页面/布局变化时清理。验证：禁止联网的合成mock、调用记录和状态测试。
- A6：按钮、日历和提示具有可用的键盘焦点、日期标签与描述；区域重绘后无失效引用和重复事件。验证：键盘旅程/DOM检查。

## Data Criteria

- A7：合成流水覆盖费用、退款、到账/pending、边界日期、闰年/跨月、零和负投入。结果与既有propSum口径一致，货币精度到分，原数组不被修改。验证：node:test。
- A8：累计走势按日期排序并合并同日记录，从0开始且终点等于净收益；空/异常日期不伪造记录，长区间不按每个空白日无限展开。验证：node:test和边界样例。

## Component Criteria

- A9：领域计算与UI控制分离，复用component-impact-map列出的接口；新增样式只影响现代Prop，不重置全站主题变量。验证：代码审阅、选择器检查、打包/语法检查。

## Verification Surfaces

- Facticity：源码/实际渲染与规范对应，无虚构结果或未执行测试声明。
- Static：npm run bundle、node --check、双语键和modern样式边界。
- Unit：npm test及新Prop范围/走势/状态测试。
- Redteam：非法日期、极值、注入字符串、跨身份残留、禁止网络路径。
- E2E：只用合成离线mock加载真实源码，检查范围选择、筛选、提示、重绘。
- Sensory：桌面/手机、明暗/配色/中英与经典回归；最终本地效果交由用户查看。

## Unresolved Gaps

无。尚未实施或验证的断言不得标记为passing；机器记录见acceptance.json。
