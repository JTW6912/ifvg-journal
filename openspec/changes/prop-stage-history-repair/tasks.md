# Tasks: prop-stage-history-repair

## 1. 从漏斗定位需要核对的账号

用户结果：用户从漏斗右上带数量的「数据检查」进入待处理 / 全部账号名单，按账号或公司搜索，看到明确的缺失与疑似问题和公司 Logo；浏览不产生任何数据写入，也不受财务日期过滤截断历史。

- [ ] 1.1 实现并测试纯问题分类与原始快照保护：购买/阶段有效日期、免考例外、多次考核、疑似顺序/重复、非法历史结构标记；不推算、不去重、不修改输入。
- [ ] 1.2 接入紧凑漏斗入口与只读检查抽屉，复用当前公司/分组范围、真实目录 Logo、现有模态根和双语主题；保留原统计与经典展示。
- [ ] 1.3 用合成数据验证名单、搜索、空态/只读、身份与页面清理、焦点和手机表现，并完成此片独立规格/质量审阅记录。

## 2. 安全地修正并核对单个账号历史

用户结果：用户在沿用原样式的横向状态时间线上补录、修改、标记移除或恢复历史记录，核对前后差异再保存；当前状态、续费、余额和全部收支流水保持不变，冲突或失败时不会静默覆盖或丢失草稿。

- [ ] 2.1 实现并测试不可变历史草稿、稳定记录标识、显式插入、校验、移除/恢复及最小差异；未知事实可保留但不自动补成今天。
- [ ] 2.2 新建仅购买日期/阶段历史的 owner 条件更新与返回校验；覆盖空版本、原历史/购买日期比较、零行、错误、会话切换、重复提交及受保护字段/流水零写入的 mock 证据。
- [ ] 2.3 接入横向圆角日期/状态编辑器、确认页、删除确认、busy/取消/保留草稿/冲突重载；复用既有样式与弹窗生命周期，不引入另一套业务运行时。
- [ ] 2.4 保护旧时间线及父表单接缝：不得再仅凭首项索引修改购买/费用日期；未保存详情草稿不丢失、不在修正后回写旧日期；不改正常购买/记账/状态推进的独立规则。
- [ ] 2.5 完成保存后的统计联动及全量离线回归、中英/主题/手机/键盘/安全检查，取得独立审阅和原生开发验收交接回执；不以原型或真实页面浏览代替正式验证。
